# A capability is one /v1/<name> the cloud serves — the app, per HIP-0139 —
# grouped into a domain by hanzoai/openapi's capabilities.yaml. The rule is one
# capability, one HIP, declared by that HIP in front matter:  capability: <name>
#
# Adding a line here is how a NEW capability ships before its spec is written.
# Deleting one is how a capability gets its HIP -- and the deletion happens in
# the SAME commit as the HIP, because scripts/coverage.py fails (CV002) on a
# line whose capability is now declared. Neither half can rot.
#
# `python3 scripts/coverage.py --report` names, for each line, the HIP that
# already talks about that route -- usually the one that should adopt it.
